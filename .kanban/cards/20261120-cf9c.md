# A readable page for a browser when serve refuses

## Why
A person who opens an app's link in a browser and is refused (a host the server does not answer to, a missing or old token, a contract it does not serve) sees the raw JSON envelope. A browser should get a short page saying what went wrong, why, and what to do; a program keeps the envelope as it is.

## Changes
- serve tells a browser from a program: a page path, a navigation (`Sec-Fetch-Mode: navigate`), or an Accept that prefers text/html gets the page; `/api/` with Accept application/json, or no navigation, gets the envelope unchanged.
- One page for every refusal serve's guard and handler give, built from the Problem: what, why and what to do, per reason. The link page and the unreadable-token page become it too.
- The token never appears in the page or the log; the page is no-store with no referrer.
