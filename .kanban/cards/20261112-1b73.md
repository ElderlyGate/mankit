# Docker Desktop: a new servers folder reads as root's for a moment

Found in e-designer E3a (e-designer card KBN-20261112-0e6b) while smoke-testing the board image on macOS with Docker Desktop.

## Repro
1. Run an app's `serve` in a container on Docker Desktop (macOS) as the machine's user (`--user 501:20`), with the app's data folder bind-mounted from the host and no `servers/` folder in it yet.
2. Within the first second after serve starts, ask `GET /api/version` or run `<app> servers link` in the container.
3. `servers link` says `<data>/<app>/servers belongs to another user (uid 0)`; the API answers 500. A second later both work, and `stat` in the container shows uid 501 for the folder and the token. A restart with the folder already there is fine.

## Effect
On a first start only: a brief 500 from every API request, and `servers link` fails, until Docker Desktop's file sharing reports the real owner. Linux is not affected. Tools that wait for the server (e-designer's install.sh) get through.

## Fix idea
In `readToken` (`privateDir` / `private` in attrs_unix.go), when the owner check fails, wait a short moment (about 200 ms) and stat once more before refusing; refuse only if the second look agrees. A test fakes the first stat.

## Done when
- A first start on Docker Desktop answers no 500 and `servers link` works at once; a folder really owned by another user is still refused.
