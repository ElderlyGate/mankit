# live events (mankit serve step 2b)

Step 2 of epic 20261111-0ff3, second part. Decisions: ADR-E1, E2, E3, E6, E9, S04; block CLI-API in the constitution design.

- Package `events`, attached to the app's feature list (`events.Attach`); no handler calls it and no route names an event (G-CODE-7). A change route says the thing it changes (`serve.Change`); events' config names the event each route causes; serve tells the attached module of each change answered well, or that it missed one while off.
- The event: CloudEvent 1.0 in structured JSON (id, source `/<product-id>/<thing>`, type `<product-id>.<thing>.<verb>` checked against the app's catalog at start, subject, time, datacontenttype, data, the request's traceparent and tracestate).
- `GET /api/events`: Server-Sent Events, `id:` the event id, `data:` the event, heartbeat comments, `Last-Event-ID` replay from a bounded ring, at most 64 streams, behind serve's guard.
- `<product-id>.stream.gapped` for a client that missed events: too old, another server, the feature off meanwhile, or an event that could not be built (contracts mankit/v1, ElderlyGate/contracts#3).
- Feature closed: `/api/events` answers 404 `not_found` and nothing is kept; switching it off ends streams at once. An app without events serves the same routes.
- Events validate against contracts `event/v1`. No CLI command: the decisions call for none.

Not here: telemetry (step 4), e-designer using it (card 3abf).
