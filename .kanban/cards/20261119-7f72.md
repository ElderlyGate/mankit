# mankit v4: the store below serve, settings and ask

## Why
One route (ADR-S22, owner 19 Nov): mankit's own files go through the store with turns, like every app's. The store imported serve, ask and queue, and queue imported settings, so serve, settings and ask could not use the store without an import loop. Keeping v3's API with aliases is a break for gorelease, so the owner chose a major (19 Nov): v4.

## Changes
- Module path `github.com/tugbayatilla/mankit/v4`.
- New package `problem`: Problem, Place, Fail, FailAt and the Problem types, moved out of serve.
- The queue's turns move to `store/internal/queue`, the store's own, which Go keeps every package outside the store from; the package `queue` moves to `store/queue` and keeps showing the line (`queue.List`) and setting its waits (`queue.Settings`, `Waits`, `WaitKey`, `LimitKey`, `ConfigCommand`). No public `Change` is left: a change takes its turn through `store.Scope.Change`.
- `store unfinished` moves to `store/cli` (UnfinishedCommand, UnfinishedRoutes and their kinds and paths).
- `home.Migrate` and `home.CopyOnce` move to `store`; `home` only names paths (`home.MigratedMark`).
- The deprecated `Scope.Clear` is removed; `ClearShown` stays.
- v3 freezes: no backports unless a security fix.
- Nothing writes differently yet; PR2 (card 20261119-addd) moves the writers.
