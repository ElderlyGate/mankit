# logs: records in OpenTelemetry's shape, the logs folder, telemetry

## Why
The owner's log decision (19 Nov): logs always written locally in OpenTelemetry's log shape through log/slog; a detached server writes them to the logs folder (G-STACK-8 as changed: ~/.local/state/elderlygate/<app> on Linux, ~/Library/Logs/elderlygate/<app> on macOS, rotated at 10 MB, five kept); logs are allowed outside the store (ADR-S22 as changed); sending them over OTLP is the enterprise telemetry feature, off by default (ADR-E5, E9).

## Changes
- `home.Logs()` and `home.ProductLogs(id)`.
- Package `logs`: an slog handler writing OpenTelemetry's log data model as JSON lines; a Problem as an attribute in its problem/v1 shape; `logs.Writer` for what logs through a writer; `logs.Open`, a log file rotated at 10 MB with five kept; `logs.Telemetry` and `logs.Export` over OTLP (the OpenTelemetry modules, used only when the feature is on).
- serve: a foreground server logs to stdout, a detached one to its file in the logs folder (its record names it); a broken feature is a WARN record with its Problem; the link with the token never goes into a log.
- The store's and the queue's notices are records on stderr by default.
- `internal/encode` is the one JSON and YAML form (helpout.Encode, the store, config.yaml); `internal/disk` moves under the store, so nothing outside it writes past the port.
