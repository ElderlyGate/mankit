# Read-back follows a later move in the same change

## Why
Found by e-designer#122 (`design rename`: name, note and move in one change). In one change, Put `a/x.yml` then Move `a` to `b` failed `not_read_back`: the read-back checked `a/x.yml` as its Put left it and ignored the folder move after it. v3.11.0 still has it.

## Changes
- The read-back checks each written key where the last write leaves it. A folder move takes along what was written inside it, and drops what was there under its new name before.
- One rule for a move, `Key.rebase`, shared by a change's view, its list and the read-back.
- Conformance: put then folder moved; put then file moved; folder moved then put into it; put, moved and moved back; a folder removed then another moved to its name. Crash case: a file written, then its folder moved.
