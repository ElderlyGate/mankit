# store: removing a folder and writing a file at the same key in one change fails

Found while building mankit#98 (licenses: `license-active` that is a folder).
One `Change` that does `tx.Remove(key, store.Anything())` on a folder and then
`tx.Put(key, body, …)` at the same key fails at read back: "`<key>` was written
but could not be read back as written". The folder is removed and the file is
written; a likely cause (unconfirmed) is read back checking each file the
folder held to be gone with Lstat, which now meets a file on the way and fails
with "not a directory" rather than "does not exist".

Today `licenses.choose` works around it with two changes (remove the folder in
the scope's own turn, then put the file), which leaves a window between them.

Done when: one change can remove a folder at a key and put a file there, read
back passes, and a store test covers it (and the reverse: a file removed and a
folder made at the same key).
