# serve: Route.ActionFor, a change that asks by its request

For e-designer E4c-2b (e-designer card KBN-20261112-c3b1): mankit's 428 becomes the only confirm for every route of e-designer's board, the proxied Node routes included, so a route's question must be able to depend on the request. Decided by team-lead on 2026-11-14.

## Changes
- `Route.ActionFor func(*http.Request) (ask.Action, bool)`: the change one request makes, and whether it asks at all. A request that only follows a yes already given, rehearses, or changes nothing the person is asked about goes through unasked; a request may ask as the type it says.
- Action stays required for a change and names the route's type, used when ActionFor gives an unknown one; a change to the system itself always asks, whatever ActionFor says.
- Handler refuses ActionFor on a read.
- The doc comment says it plainly: the confirm is a question to the person, never a guard; the token is the guard.

## Done when
- Tests both ways: a request that does not ask needs no yes, any other gets 428; a type from the request resolves its own style; a system change can be neither skipped nor lowered; ActionFor on a read is refused. Released as v3.3.0.
