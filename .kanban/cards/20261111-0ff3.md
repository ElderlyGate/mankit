# mankit serve: the shared server for every app

Same-shape step 3. Home of the decisions: ADR-S04 (mankit serve), S05, S07, S08, S09, S14, S15, S19 and E1-E9 in the constitution design; block CLI-API says what it holds. This card only orders the work.

Taken from kanban's server (internal/api guard.go, confirm.go, server.go; internal/serving), the most complete of the four copies. e-designer uses it first (ADR-S11), kanban later.

Order, one pull request and one release each:
1. serve core: the guard (link token to a Strict cookie, the header, Host and Origin checks, JSON only), 428 without confirm=yes, GET /api/version with Accept-Contract and 406 unsupported_contract, answers and errors in the contracts envelope with ran (ADR-S08), serve --detach, servers, servers stop, servers link, every record file with apiVersion and kind (S15).
2. events: GET /api/events as SSE carrying CloudEvents 1.0 with traceparent, Last-Event-ID resumes; its own module, switchable (E9, G-CODE-7).
3. change queue (S14): tickets in <served folder>/<app folder>/.queue/, one change at a time, done once written and read back.
4. features: the values a feature needs and whether it starts on or off (G-CODE-8).
5. then e-designer moves to mankit serve (card 3abf in e-designer).
6. after e-designer: telemetry (E5): OpenTelemetry over OTLP, built as a G-CODE-8 feature that starts off and needs OTEL_EXPORTER_OTLP_ENDPOINT; and connect, connections, disconnect, token storage, names and patterns (S7, S8, S9).

Tests: one file per command with the six parts (ADR-S19); the shared helpers live here.
