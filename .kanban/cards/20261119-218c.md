# features reads and writes the `<id>: on/off` section

Minor release of mankit.

## Format

Today (e-designer `config.yaml`, `appconfig.go`):

```yaml
features: {off: [projects], on: [tracing]}
```

New (owner-approved format, 19 Nov 2026):

```yaml
features:
  projects: off
  tracing: on
```

Rules:
- Each entry is `<feature-id>: on` or `<feature-id>: off`, nothing else (no true/false, no yes/no).
- A feature not listed keeps its default: on, or off for the features that start off.
- Listing a feature at its default is allowed and changes nothing.
- An unknown feature id is refused by `config apply`, naming the file and the id; elsewhere it is reported, never silently ignored.
- The old `off` / `on` lists are read once more and rewritten in the new form by `e-designer format --write` (a one-level upgrade); after that only the new form is read.
- One home: reading and writing this section moves into mankit `features`, so every app with a feature list uses the same form.

## What this card does

- `features` gets the reader and the writer of the `features:` section in the new form, so no app writes its own.
- The reader refuses an entry that is not `on` or `off`, and reports an unknown feature id with the file and the id.
- The reader accepts the old `off` / `on` lists once, for the upgrade; the writer only writes the new form.
- Tests for: every rule above, the old-list read, a feature listed at its default.
