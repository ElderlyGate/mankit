# Contract versions convert both ways in one place

## Why
ADR-S16 as changed: an app reads in every contract version its down steps reach, and says so in each such answer (`converted_down`, with what was lost); it takes writes in its own version and the one before, keeping the fields the older form cannot hold, and refuses an older write with `unsupported_contract`; each version step converts up and down in one place; the version answer lists the versions an app reads and writes. Read or write is told by the HTTP method and route, and by a CLI command that asks and takes a store turn; there is no second list.

## Changes
- An app's contract steps, each converting up and down, in one place in mankit; serve answers a read in the asked version by stepping down, and takes a write from the version before by stepping up.
- The version answer lists the read and write versions.
- The contracts changes this needs, with the owner's word first.
