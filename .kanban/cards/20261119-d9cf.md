# store journal keeps a file's mode

## Why
After a crash the store puts a removed file back 0644 in a served folder and 0600 in the own scopes, because a journal line holds no mode (mankit#47 review M2). Owner, 19 Nov: accepted for now; the mode comes with the next store contract version. contracts store-journal-change says a field a newer app adds never changes how a line is put back, so the mode cannot be added to the v1 line.

## Changes
- contracts first: a new journal line kind or a new store version whose file lines carry the file's mode (cross-board, a contracts card names it).
- The store writes the mode on every file line and puts a removed or replaced file back with it; it still reads v1 journals, putting them back as today.
