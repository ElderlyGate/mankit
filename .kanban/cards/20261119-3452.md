# mankit contracts client: one reader, two transports

## Why
ADR-S00 and ADR-S02: a reader of another app uses one shared client, the CLI on the same machine and HTTP with a token anywhere else, and that client lives in mankit for every Go app. mankit has the server side (`serve`) but no client. control-room's product connector is its first user (control-room board, KBN-20261117-2c29; decided by the owner on 19 Nov 2026).

## Changes
- One client package: ask an app for a contract and get the envelope's `data` and its Problems back, the same way over both transports.
- CLI transport: runs `<command> … --contract <v> -o json` on this machine.
- HTTP transport: `Accept-Contract: <v>` with the token of a `server connect`ed server.
- It asks `version/v1` first and picks the highest contract both sides support; `unsupported_contract` comes back as a Problem (ADR-S03), decided by its code (G-STACK-15).
- No app-specific code: an app is its command, or its address and token.

## Done when
- [ ] Both transports answer the same JSON for the same contract, tested against the contracts samples.
- [ ] A test app over each transport, and the Problem path for an unsupported contract.
