# mankit v2: Bearer token, token renew, smaller surface

Owner decisions of 12 Nov 2026; mankit moves to v2.0.0 so apps move once.

Plan:
1. The token stays only in mankit, in `<data>/<app>/servers/token`; every client gets in through `servers link` (ADR-S00, S04, S14).
2. Every app takes the token as `Authorization: Bearer <token>`. The per-product header and `App.TokenHeader()` go. Cookies stay per product and port.
3. `servers token renew` asks for the name (G-STACK-6; `--yes` skips), writes the new token whole (G-CODE-5), and running servers take it on the next request: the guard checks the file's mtime and rereads only when it changed. The old token is refused at once. A refused page says to open `servers link` again. An unreadable or insecure token file is refused, never a fallback.
4. Every breaking change at once: exported names no app in the org uses are hidden; the rest is kept.
5. gorelease in CI fails a public API break that is not a declared major.
6. Module path `github.com/tugbayatilla/mankit/v2` everywhere; `feat!` with a `BREAKING CHANGE:` footer.
