# features: needed values and default (G-CODE-8)

## What

G-CODE-8 in mankit: a feature is on or off only by its own switch, lists the values it needs, starts on or off, and fails by itself when a value is gone. A part the app cannot run without is not a feature: a value it needs stops serve at start. Events starts off (ADR-E9). No telemetry.

## How

- `features`, additive only (no breaking change, V-3): `Feature.Needs` and `StartsOff`; optional `Store.On` keeps the owner's on for a feature that starts off; `List.WithLookup` says how a value is found; `Set` on without every value is refused with `feature_needs_values` naming each; `State.Missing`, `On` and `Broken` show a feature that is on but broken; `Attach` refuses a list that cannot answer for its features.
- `serve`: a broken feature's routes answer 503 `feature_needs_values` and its module hears only that it missed a change; one start log line per broken feature; `Site.Needs` and `Site.Lookup` refuse a start without a core value (`needs_values`).
- `events.Feature` starts off.
- README and the design block CMP-FEATURES say the rules.

## Done when

`go test -race ./...` passes with tests for: a refused switch-on naming every missing value, switch-on once the values exist, a feature that starts off and its kept on read by a fresh list, a feature on that loses a value is broken while the others work, closed and missing is off by the closer, closers still win, existing default-on behaviour unchanged, serve's 503 and 404, the start log line, serve refusing a missing core value, and switching and asking at once under -race.
