# servers lists each server's address and how to sign in

Owner, 2026-11-16: "i used servers command and it showed me the information of the servers but didnt give me the links at all! ... if i am getting servers information, it would be nice to get all related information". Decided: a card for after same-shape; keep today's behaviour until then.

## Why it is not there today
The link `servers link` prints carries the machine's token, so it works like a password. `servers` is a list that may be pasted or kept in terminal history, so the token-carrying link was left out of it.

## Change (after same-shape)
- `servers` shows each server's plain address, for example `http://127.0.0.1:7799/`. It carries no token; with the cookie from an earlier link, it opens the page.
- Under the list, one line: "`servers link <addr>` prints the link that signs you in".
- Optional: `servers --links` prints the list with the sign-in links, only when asked.
- `-o json` gains the plain address per server (never the token), described in the contract.
- One home: mankit serve, so every product's `<app> servers` (control-room, e-designer, kanban, the rest) changes at once.

## Done when
- `<app> servers` shows the address and the hint; `--links`, if built, shows the sign-in links; no token appears without being asked.
- Tests cover the list, the hint, `--links`, and that the plain list never holds a token.
