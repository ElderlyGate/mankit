# Check the Strict cookie link page in a real browser

serve sets the token cookie SameSite=Strict (block CLI-API). A link opened from another site (such as control-room) gets a page that goes on to the app by itself, instead of a redirect, because a browser drops a Strict cookie set on a redirect that began on another site. The tests check only the headers and the page.

Do this when e-designer first uses serve: open an e-designer link from another site's page in Chrome, Firefox and Safari, and check the page opens with the cookie set.

Also check that the link page replaces its history entry (location.replace), so the link with `?token=` is not kept in the browser's history, and that a browser without scripts still goes on through the refresh.
