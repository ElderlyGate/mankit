# The CLI answers a Question and takes --confirm <id>

## Why
contracts question/v1 says a command with no terminal answers a Question instead of changing anything, exits 3, and takes the yes as `--confirm <id>`. serve's gate does this over HTTP, with its ids kept in the server. A CLI run ends, so its ids must be kept across runs.

## Changes
- A command that asks, with no terminal and no `--yes`, prints the Question answer (`-o json` or a table) and exits 3.
- `--confirm <id>` takes it once, bound to the command path, its flags and arguments, and what it reads.
- The ids kept across runs in the app's data folder through the store: a form on disk, with its schema in contracts first.
