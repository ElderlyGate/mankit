# mankit store: port, files adapter, inner safety core and storetest (v3.8.0)

## Why
Step SP3 of the storage-port epic (constitution card KBN-20261114-f239, ADR-S22). One port in mankit keeps every app's writes and owns the safety rules once.

## Changes
- New package `store`: Scope, Tx, Key, Want, Served, Config, Data. Reading never takes a turn; every change goes through `Change` (takes the thing's turn, all or nothing, read back).
- An app's own Config and Data scopes take a turn too, in `<scope>/.queue/`; there is no separate Lock.
- The inner safety core, shared with `queue`: stay in the scope, no links out, whole writes only if the thing still holds what was read, private app folders.
- The files adapter, moved from e-designer `internal/files` (write, inside, nonblock, journal, undo) and from its bundle code (lock, own home, recovery, keep-aside). The journal lives in the writer's own data folder, one per machine, in the StoreJournal shape (contracts SP2). The old `/tmp` recovery is not carried over.
- One open root per scope; a change with a single write skips the journal.
- The adapter is chosen in one spot inside `store`, behind the feature list (G-CODE-7, ADR-E9), so an enterprise adapter later adds a module and a feature entry, nothing else.
- `storetest`: the one conformance suite, written so any adapter can run it, with crash injection per operation; the link and race tests move from e-designer.
- Additive only: nothing exported is removed.

## Waits on
- Constitution SP1 KBN-20261119-08f7 and contracts SP2 (contracts board, "problem/v1 store reasons and mankit/v1 StoreJournal"); pinning the contracts head before its release is fine. Cross-board links are not supported, so named here.
- Runs side by side with the thing-first gate (a79c, d1c2, f83b); if both are ready, the thing-first release goes first. The store carries over unchanged into v4.0.0 (0f8b).
