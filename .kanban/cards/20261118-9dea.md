# serve --detach fails when started in a folder that is gone

`serve --detach` starts the child in the caller's working folder: `detach` takes `os.Getwd()` (serve/command.go:273, v3.6.0) and `spawn` sets `cmd.Dir = dir` (serve/process.go:34). When that folder has been deleted, either Getwd fails (ENOENT), or, on macOS where Getwd answers from $PWD, the child's chdir fails and `cmd.Start` reports `cannot start <binary>: fork/exec <binary>: no such file or directory`.

Found in e-designer step E7b (e-designer card KBN-20261117-7b28, e-designer#101), where `e-designer serve` must work from any folder, even one that no longer exists.

## Changes
- A detached server starts in a stable folder: the records folder or `/`, not the caller's working folder. A server needs no working folder of its own; an app that wants one names it.
- A test: detach from a folder removed after the chdir starts the server.

## Then
- e-designer removes its stopgap: serve's `PreRunE` chdir to `/` when a host serve's folder is gone (src/cli/internal/cli/serve.go).

## Done when
- `serve --detach` started in a deleted folder serves, on Linux and macOS.
