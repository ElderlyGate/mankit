# CLI client mode: commands go to a remote server

## Why
An app's CLI works on local files. When the app runs as a server elsewhere, such as a team's board on another machine, the same commands should reach it, through the same contract the API answers, instead of a second client.

## Changes
- `<app> server connect <url>` keeps the address and the token once. The token goes to the system's keychain or secret store (macOS Keychain, the Secret Service on Linux), never to a file others can read and never to a log.
- Every command can go to such a server instead of local files, such as `shop shelf list --server team`, through the same contract as the API, answering the same envelope.
- A change that asks: the CLI shows the server's Question in the terminal and confirms with its one-time id; over HTTP there is no `confirm=yes` (see ask.Question). `--yes` answers the question locally, without a prompt.
- Listing and dropping connections: `<app> server disconnect <name>`.
