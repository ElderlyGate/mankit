# licenses: start or renew the built-in trial

## Why
On its first start with no license an app starts a 14-day trial by itself, a reinstall gives a fresh trial, and a bought license is never touched (ADR-L9). That rule lives once, here, so every app behaves the same.

## Changes
- One call an app makes at start, passing its embedded release-trial key and its executable's path.
- No license at the app's place and no org license: it writes the embedded key as the app's license file, at the place `license add` writes a product license, with `spec.started`: today, the binary's path and its file time (the install stamp). Only while today is not after the key's `until`.
- The only license is a release-trial and the running binary's stamp differs from the file's `started` (a reinstall or update writes the binary fresh): it writes a fresh trial for `days` from today.
- A bought license, product or org, is never touched, and no trial is written then. A person's trial key is never replaced.
- A release-trial whose stamp matches is left alone, ended or not.
- Writes go through the same store as `license add`; a failed write leaves the old file whole and is reported, never fatal to the app's start.

- The contracts card for the started record (License file: an unsigned started record for a release trial).
