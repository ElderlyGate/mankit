# ask: one way every CLI asks before a change

Plan: constitution design `plan-confirm-changes`, block CLI and question QST-TUI.

## Do
- Package `ask`: `ask.Flag(cmd)` adds `--yes` ("make the change without asking"); `ask.Change(cmd, ask.Action{Type, What, Name, System}, style)` returns a yes with `--yes`, asks in the style on a terminal (`name`: type the name, `yes-no`: `Proceed? [y/N/a]`, `never`: no question), and refuses with no terminal (`refused: <what>; pass --yes to make the change`). A command without `--yes` is an error of the app.
- Every type defaults to `yes-no`, delete included; a change to the system itself (`System: true`) defaults to `name`, and a remembered `never` does not silence it, only `--yes` does.
- `ask.Resolve(action, styles)` is the style in use and its source; `ask.Load`, `ask.Set` and `ask.Remember` read and write the `confirm:` section of the app's config; `<app> set config confirm.<type> <style>` sets one.
- A refusal is `ask.ErrRefused`; `helpout.Execute` exits 3 on it, so a caller can tell a refusal from a failure.
- `confirm`: the TUI asks `[Y/n] enter = yes`: y, Y or Enter says yes, any other key cancels (QST-TUI).
- Table tests; README documents `ask`.
