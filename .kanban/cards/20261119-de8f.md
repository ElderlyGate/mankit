# store.ListIn lists a folder inside a change

## Why
e-designer#122 (card 9bbb) lists a design's files inside a change, seeing what the change itself put, removed and moved. Without a list in the change it would keep a second view of its own. A method on `store.Tx` would break the public API (gorelease), so it is a function beside it.

## Changes
- `store.ListIn(tx, prefix)`: every thing at or inside prefix as the change has it so far, in the order `Scope.List` gives.
- storetest conformance case: a list inside a change sees its own writes, matches `List` once made, refuses a key outside.
- README store section names it.
- No contracts change: a key list is not a stored form.
