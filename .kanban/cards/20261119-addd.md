# mankit's own writers through store scopes, one route

## Why
ADR-S22: every app keeps what it writes through the one storage port, and mankit is no exception (owner, 19 Nov: one route, no ADR change). SP4 (card 20261119-f862) left mankit's own writers on the safety core `internal/disk`, below the port, taking no turn. PR1 (card 20261119-7f72, v4.0.0) broke the import loop that kept them there.

## Changes
- `store.Own(dir)` opens a folder an app's file is in as an own folder, private to this user like `store.Config`; `store.EditFile(path, edit)` reads, changes and writes one file in that folder's turn. A path-taking API (an app may name a folder of its own, such as `HUBMAN_CONFIG_DIR`) goes through them.
- settings, ask (and so prefs), usercmd, palette, split, `store.Migrate`'s mark and `store.CopyOnce` write through the store, each in a turn, all or nothing.
- serve's records and token go through the app's data folder in the store; the token's flock goes, as the turn does its work. A server forgets its record before its listener closes, so it writes nothing once a stop saw it stop.
- A `config.yaml` that is a link is refused, never followed and never replaced (ADR-S22: nothing follows a link out; owner, 19 Nov). Reading it is unchanged.
- `store.CopyOnce` refuses a folder holding a link: the store writes no link.
- The disk writers nothing uses any more go (`WriteFile`, `Replace`, `WriteOnce`, `CopyOnce`, the no-replace rename).
- The server's log, and `internal/disk` moving under the store, come with the log writer (separate card).
