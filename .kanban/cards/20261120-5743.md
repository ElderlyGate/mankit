# Site.ErrorPage: an app draws serve's refusal page in its own look

## Why
serve's refusal page for a browser carries its own small styles, as mankit cannot depend on the private UI kit. An app that draws its pages with the UI kit may want the same page in its own shell.

## Changes
- An optional `Site.ErrorPage` that gets the page's view (title, detail, why, what to do, status) and draws it; without one, serve's own page.
- The UI kit gives a partial for it.
- Look again at what a detail may show a remote browser: a config_unreadable detail can name a machine path, shown before any token check when --allow-remote is on (as the envelope already did).

## Done when
- [ ] An app can draw the refusal page with the UI kit, and serve's own page stays the default.
