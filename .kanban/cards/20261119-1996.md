# license: signed license files, Has, license show and add

## Why
Step S4 of the license epic (control-room card KBN-20261106-e99b): the checking part is mankit's (ADR-L7), used by every app. ADR-L1, L3, L4, L5, L6, L8, L9; the answer is contracts mankit/v1 LicenseShow (contracts#46).

## Changes
- The license file is a Resource (ADR-S15): `apiVersion`, `kind: License`, `metadata.id` equal to the signed payload's `id`, `spec` with the payload and signature; a file whose two ids differ is refused as `id_mismatch`.
- Package `licenses` (named like `features`; a folder `license` cannot sit beside `LICENSE` on macOS): the license file's one Go type, Ed25519-signed and offline (L1): who it is for (L4), its kind org, product or trial (L8, L9), its products and enterprise features, issued, until and the key id (L6). `Sign` for nw-license with its signer, `Verify` against the keys the app's build trusts, prod keys on a release and dev keys on any other build (L5).
- Reads the org license and the app's product license from mankit home's folders (L8); a file it cannot read or verify is refused with its file and reason (G-CODE-6).
- `Has`, a `features.Closer` by license that locks every enterprise feature no running license or trial opens (L2, L3, L9), days left and ended.
- `licenses/cli`: `<app> license show` (contracts LicenseShow) and `<app> license add [--org] <file>`, which verifies first, asks y/N and writes the file whole through the store.
