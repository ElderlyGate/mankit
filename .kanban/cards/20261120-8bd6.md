# ask.Question: 428 Question with a one-time confirm id

## Why
A change that asks first is answered today with 428 and a bare `unconfirmed` Problem. Contracts question/v1 gives it one shape for every app (ADR-S04, G-STACK-13): a Question answer with a one-time id, the change's type, whether it changes the system itself, how it asks and what will change. The reader confirms by sending the same request again with that id, once, before it expires.

## Changes
- `ask.Question` and the one home that makes, keeps and takes question ids: bound to the request (method, path, query, body sum, type), kept a few minutes, taken once.
- serve's gate answers a change that asks with 428 and a Question answer; `confirm=<id>` runs it once.
- `confirm=yes` and `confirm=remember` become old forms (owner, 20 Nov, for security): still taken in v4, removed at the next major (card 20261117-0f8b). Over HTTP the yes is the Question's id, remembering is `confirm=<id>&remember=yes`; the CLI keeps `--yes`.
- The CLI's side (`--confirm <id>`, the Question with no terminal) needs its ids kept across runs, a form on disk with its contracts schema: its own card.
