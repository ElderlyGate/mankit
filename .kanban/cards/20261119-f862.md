# mankit's own writers through the store, and the storage wall in CI

## Why
Step SP4 of the storage-port epic (constitution card KBN-20261114-f239, ADR-S22): an app writes no file outside the port, and a CI check fails a pull request that does (G-GIT-12). mankit goes first and ships the wall every app turns on.

## Changes
- mankit's own writers move onto the store: `internal/configfile` merges into it and goes; serve/servers, settings, prefs, ask/config, usercmd, palette, split, `home.Migrate/CopyOnce`; queue tickets through the inner core.
- The wall: a lint config in mankit's CI, plus one shared config every app turns on. It forbids file-writing calls (`os.WriteFile/Create/OpenFile` with a write flag, `Rename`, `Remove*`, `Mkdir*`, `Chmod`, `CreateTemp`, `syscall.Flock`) outside the store core. YAML or JSON encoding is allowed in exactly two homes: the store and helpout.
- Each app's own exceptions (installs, user exports, test temp folders) go in its lint config with a reason; its project constitution names them.
