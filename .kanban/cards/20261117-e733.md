# servers --check <addr> asks one server and deletes nothing

Found in the review of e-designer#91. Every board container and the host share one servers-records folder, and `servers --check` lists through `live`, which deletes every record it cannot reach. A container's HEALTHCHECK would then delete the host's records every 30 s. All boards write the same `0.0.0.0-5173.json`, so one board stopping makes the others unhealthy, and the check passes on another container's record. Owner decided the fix: a check of one address.

## Change
- `servers --check <addr>` asks only the server at addr (at loopback for an every-address one) and deletes no record. Its answer is the same envelope as `servers`: kind ServerList, the records listed for that address with whether it answered, read and left in place. A server that does not answer is a Problem of type not_found with reason not_answering in errors, and the exit is non-zero (helpout.Printed). none_listed does not apply: a record is not needed to answer.
- `servers --check` without an address stays as it is.

## Done when
- Tests: an answering addr gives no errors and exit 0; one that does not answer gives not_answering and a non-zero exit; no record is deleted either way; -o json gives one envelope.
