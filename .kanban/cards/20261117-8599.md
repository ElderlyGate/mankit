# servers --check fails unless every server answers

Owner, 2026-11-17: a board image's HEALTHCHECK asks `<app> servers --check`. It exits non-zero unless every listed server answers (e-designer#91, after mankit#40). The plain `servers` and its answer keep their meaning: a record left behind shows as not answering, which is not an error.

## Change
- `servers --check` lists the same servers, and fails unless at least one is listed and every listed one answers. A failure is said in the answer's errors (ADR-S03: errors is empty only when the answer is good): one envelope, kind ServerList, data unchanged, and a Problem of type `not_found`. In a table, the reason goes once to standard error.
- The failure comes back as `helpout.Printed`. `helpout.Execute`, the shared runner, exits 1 on it and prints nothing more, so -o json stays one envelope in every app that runs on it. e-designer's own runner adopts it in card KBN-20261117-82ca (e-designer#91).

## Done when
- Tests: every server answering, no errors, exit 0; one not answering or none listed, one envelope with the reason in errors and the same data; helpout.Execute exits 1 on Printed and prints nothing more.
