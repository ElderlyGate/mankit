# servers --check fails unless every server answers

Owner, 2026-11-17: a board image's HEALTHCHECK asks `<app> servers --check`. It exits non-zero unless every listed server answers (e-designer#91, after mankit#40). The plain `servers` and its answer keep their meaning: a record left behind shows as not answering, which is not an error.

## Change
- `servers --check`: the same answer, then exit non-zero when a listed server does not answer, or when none is listed. The answer is printed once: with -o json or yaml no second envelope follows, as the refusal comes back as `serve.AlreadyAnswered`, which tells the app the answer is given and only the exit status is left. In a table, the reason goes to standard error.
- Help says it.

## Done when
- Tests: every server answering exits 0; one not answering, or none listed, exits non-zero; with -o json the output is one envelope, the same as without --check.
