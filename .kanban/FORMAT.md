# This board is just files

A kanban board this app can read is a directory containing:

    manifest.json   the columns, their limits, and the policies
    cards/          one file per card: Markdown (.md) or YAML (.yml), mixed
    archive/        cards swept out of Done

The manifest's card_format names only the format a new card is written in.

Nothing else. You can read it, grep it, diff it, and edit it by hand.

## Ask the tool, not this file

This file is committed, so it is as current as whenever somebody last
remembered it. Two commands are generated by the binary that is running and
cannot be out of date:

    kanban --help              every command this build has, and what each does
    kanban <command> --help    the flags, and what they mean
    kanban schema              every frontmatter key, its type, and its meaning
    kanban schema --json       the same, to parse

**If you are an agent: run those.** Do not take a verb or a field name from any
document, including this one. A guessed verb fails; a verb from `--help` does not.

To refresh this file after upgrading:

    kanban format --write

## A card

    ---
    id: 20260101-a1b2
    created_at: 2026-01-01T09:00:00.000Z
    column: backlog
    order: 0.5
    ---

    #feature

    # A short title

    Whatever you want to write.

The frontmatter above the tag line is managed by tooling. `order` is a
decimal between 0 and 1, assigned by midpoint, so moving one card never
renumbers its neighbours. Any key this app does not recognise is preserved
untouched — put whatever you like in there. Any such key comes back as
`extra_frontmatter` from both `kanban cards --json` and
`kanban show --json`, so a tool keeping its own state on a card reads it
back through the app rather than by opening the file.

The `#tag` line and the `# Title` heading are the only required parts of
the body. Everything after is yours.

`kanban schema` is the full list of keys, with what each one means and which
of them this app writes for you.

## The manifest is the rule

`manifest.json` states how this board works, and the app never rewrites it.
If you want different columns, limits, or policies, edit that file — the board
is exactly what it describes.

You can relax a rule for yourself without changing the project's file. Overrides
live in your own config, never in this repository, and every surface that shows
an effective value shows the manifest's original beside it:

    kanban config show          what is in force, and what the manifest asked for
    kanban config set ...       override one field
    kanban config clear         put it back

## Policies

Policies are named in `manifest.json`, along with the message each one gives
when it refuses. That file is the list; read it rather than this one.

A blocked move reports the manifest's own message. `--override` proceeds anyway. A
card carrying one of the manifest's `policy_bypass_tags` skips every check,
except one every board with a done column (`column_stamps.done_at`) holds:
an Epic card in the done column is closed, and is never moved out of it or made
another kind without `--override`.

## Getting around

    kanban board                        the whole board
    kanban cards --column refined       find cards; --json for agents
    kanban show <id>                    one card, body included

Every command that changes something asks first. With no terminal to answer,
pass `--yes`; it skips the question and nothing else.

`kanban --help` is the rest, and is always the current answer.
